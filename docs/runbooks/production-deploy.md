# Production deployment and rollback

Production uses prebuilt API and worker images referenced by immutable SHA-256 digests. Populate a mode-0600 `.env.production` with the variables required by `compose.production.yaml`, including database-scoped SurrealDB credentials, S3 and TLS-authenticated Temporal endpoints, TLS domain, HTTPS OTLP endpoint, query-encryption key, a pinned Jev model, and paths to mode-0600 credential and Jev key files. The API receives file secrets as read-only mounts; keep provider and database secrets outside Git. The deploy and rollback scripts load this file with a non-evaluating parser; shell expansion and command substitution are rejected.

Run `make production-preflight`, take an encrypted backup, then run `scripts/deploy-production.sh`. The deployment pulls exact images, waits for container health and verifies the public TLS health endpoint. Preserve the deployment state file with mode 0600.

For rollback, set the last known-good `MEMJEV_PREVIOUS_API_IMAGE` and `MEMJEV_PREVIOUS_WORKER_IMAGE` digests plus `MEMJEV_PREVIOUS_SCHEMA_MAX_VERSION`. Version 14 or newer is required because older binaries reject the erasure receipt and write-fence migrations. Run `scripts/rollback-production.sh`; it changes application images only. For the first deployment, use the same qualified image pair as current and previous. Future releases must retain a schema-compatible prior pair before rollout.
