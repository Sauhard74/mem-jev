# Backup and restore

Run `scripts/backup.sh` from a restricted operator host with SurrealDB authentication in `SURREAL_USER`/`SURREAL_PASS`, PostgreSQL authentication in standard `PG*` variables, a configured `mc` source alias, and an `age` recipient. The script exports SurrealDB, mirrors immutable canonical objects, dumps Temporal PostgreSQL, verifies every plaintext component, then writes only an encrypted bundle and checksum to the configured output directory.

Restore into newly created, isolated SurrealDB, archive, and PostgreSQL targets. Set `MEMJEV_RESTORE_EMPTY_TARGET_ATTESTATION` to `empty:<namespace>:<database>:<mc-target>:<postgres-target>` exactly. The `mc` target must be exactly the recovery bucket, and its exported alias endpoint must match `MEMJEV_RESTORE_ARCHIVE_ENDPOINT`. The restore independently verifies all three targets (including hidden archive versions) are empty before mutation, reconstructs required content metadata from validated canonical keys, applies `MEMJEV_RESTORE_ARCHIVE_SSE`/KMS encryption, reads every restored object through the production archive verifier, stops on the first PostgreSQL error, and requires `MEMJEV_RESTORE_HEALTHCHECK_URL` to pass before reporting success.

Schedule backups at least daily and retain one off-host copy. Perform a restore drill before launch and monthly thereafter. `mc mirror` captures current object bytes rather than version history; MemJev canonical object keys are immutable and conditional writes prohibit replacement. Supply the current mode-0700 independent erasure-ledger directory and `memjev-admin` binary to restore; the script binds replay to the recovery endpoint/bucket and replays every tombstone before its final health check. See [tenant erasure](tenant-erasure.md).
